# 二十一点 · Blackjack

一个纯前端的 21 点小游戏：原生 HTML / CSS / JavaScript，**零依赖、无构建步骤**，双击 `index.html` 即可游玩。

视觉方向是**暖色呢绒赌桌 + 纸质插画**（米杏墙面、胡桃木桌沿、中绿呢面、珊瑚红筹码、衬线标题），刻意避开了深色科技风。

本作的核心卖点是**难度即对手算法**：四档难度对应四套真正不同的庄家抽牌决策算法，并且它会把自己的推理逐条写在面板上，你能看见"这一张它为什么抽"。

## 四档对手（不同的抽牌算法）

| 难度 | 算法 | 思路 | 实测庄家优势 |
| --- | --- | --- | --- |
| 新手荷官 Trainee | 随机噪声 + 记错的定式 | 软牌容易搞混，17 定式记反，偶尔手抖多抽一张 | **−4.9%**（玩家占优） |
| 标准庄 The House | 固定阈值定式（S17 / H17） | 不足 17 必抽，17 以上按桌规停牌，零情绪零失误 | **+1.0%**（真实赌场水平） |
| 老练读牌 Floor Reader | 目标点数追踪 + 爆牌风险预算 | 盯着你已亮出的点数：落后就追，爆率超预算就宁可让你赢小的 | **+3.4%** |
| 算牌鲨鱼 Shoe Shark | Hi-Lo 真数 + 信念分布上的动态规划 | 按已出牌维护真数，折成剩牌信念分布，解出抽/停的期望值差再决定 | **+5.8%** |

两点设计原则：

- **不用上帝视角。** 高难度只使用荷官在真桌上合法掌握的信息（已亮的牌 → Hi-Lo 真数），不去偷看靴里接下来的牌序。早期版本让鲨鱼直接读剩余牌组成，实测庄家优势飙到 17%，那不是难度而是作弊。
- **难度是连续可调的。** `sharp` / `shark` 各有一个 `defer` 参数（按桌规行事的概率），用来把"最优解"压回可玩区间；`novice` 有对应的 `sloppiness` 失误率。这些旋钮可用 `node tools/sim-edge.js --scan` 成对扫描标定。

对手思路面板会逐条显示决策，例如：

```
算牌鲨鱼 · 第 3 步
停牌 EV -0.412 vs 抽牌 EV -0.281 · 真数 2.4 → 抽
要牌  16
```

若某一档这次选择退回桌规，日志会明确标注"退回桌规"，不假装是它自己的判断。

## 快速开始

1. 直接用浏览器打开 `index.html`；或
2. 起一个本地服务器（推荐，便于缓存控制）：

```powershell
python -m http.server 8000
# 访问 http://127.0.0.1:8000/
```

## 存档码（导出 / 导入）

点顶栏「存档」导出一段文本，可粘贴到别处或另一台设备导入：余额、战绩、桌规、当前难度**以及整只牌靴的剩余牌序**都会带走。

- 格式：`BJ1.` + base64url。牌靴按每张牌 6 bit 打包，312 张仅 234 字节，整码约 1 KB。
- 头部带明文 CRC32：改一个字符、口令填错都会被检出并拒绝载入，而不是载入一串垃圾。
- 可选口令：口令参与生成混淆密钥。
- **诚实说明：这是混淆 + 校验，不是密码学加密。** 它能防误改、防随便偷看，但有心人仍可还原成本地数值。UI 里也照这样写着。
- 对局中导出不会丢筹码：导出走 `serialize()`，会把桌上已下注的金额折回余额（与刷新页面的行为一致）。

## 规则说明

- 牌值：A 计 1 或 11，J / Q / K 计 10；点数不超过 21 且尽量接近 21。
- 黑杰克（首两张牌成 21）赔 **3:2**；双方同为黑杰克则平局。
- 庄家按所选难度的算法行事；桌规可切换硬/软 17（S17 / H17）。
- 分牌：两张同点牌可分成两手独立行牌，每手需等量下注；A 分牌后每手只补一张，且分牌后的 21 按普通 21 计（不吃 3:2）。
- 加倍：首两张牌时下注翻倍并只补一张牌（分牌后是否可加倍可切换）。
- 保险：庄家明牌为 A 时可买，额度为本手下注的一半；庄家成黑杰克时 2:1 赔付，否则没收。
- 提前认输（默认关闭，可在设置开启）：交回一手下注的一半。
- 牌靴默认 6 副，切牌深度可调（默认 70%），穿透后自动洗牌。

## 无障碍与适配

- 遵循 `prefers-reduced-motion`，并可在设置中手动关闭全部动画。
- 全部交互可仅用键盘完成，控件带 `aria` 语义（难度组为 `radiogroup`，弹层为 `dialog`）。
- 中英双语，语言选择持久保存。
- 窄屏（手机）下侧栏移到桌面下方，控制坞吸附在底部。

## 已知边界

- 保险按"一手"计；同一轮分牌后理论上应逐手计保，本作按首轮下注的一半计算。
- 存档与战绩存在浏览器 `localStorage`，清空站点数据即重置（可用存档码转移）。
- 载入时会丢弃进行中的那一局（桌上筹码退回余额），不跨刷新续打半局——避免恢复出非法状态。
